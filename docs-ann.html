SmartKNN ANN Backend

Accelerating KNN with high-speed Approximate neighbour Search.

Introduction

Brute-force KNN distance computation scales linearly with dataset size (O(N * D)), making inference slow on large datasets. To address this, SmartKNN optionally uses an Approximate Nearest Neighbor (ANN) backend to reduce search cost while preserving final decision accuracy.

The ANN backend accelerates candidate retrieval, after which SmartKNN applies its exact weighted distance metric to select the final neighbors.

Architecture Overview

I. Weighted Dataset Preparation
Feature masking, learned weights, and normalization.
II. ANN Candidate Retrieval
Fast approximate search for likely neighbors.
III. Exact Refinement
Final K neighbors selected using SmartKNN’s weighted distance.

Available Backends

Backend Description GPU Support Notes
brute Exact distance computation No Best for small datasets
ann Approximate candidate search Optional Recommended for large datasets

Setting backend="auto" allows SmartKNN to select ANN when available, otherwise falling back to brute force.

Internal Execution Flow

During inference, SmartKNN performs the following steps:

  1. Apply learned feature weights and masking.
  2. Query the ANN index for a reduced candidate set.
  3. Re-rank candidates using the exact weighted distance:
d(x, q) = √( Σⱼ wⱼ · (xⱼ − qⱼ)² )

Only the final selection step determines the prediction outcome.

When to Use ANN

  • < 20k samples: Brute backend is usually sufficient.
  • 20k – 150k samples: ANN recommended.
  • > 150k samples: ANN strongly recommended.

Accuracy Considerations

ANN search is approximate by design. SmartKNN mitigates this by applying exact distance refinement on retrieved candidates.

If accuracy drops, increase the candidate pool size or validate results periodically against the brute backend.

Limitations

ANN indexing may consume additional memory, requires index build time, and is less effective on extremely high-dimensional raw feature spaces.
